# Requirements

The decided functional scope of NoteDown, by area. This file describes the
current state of the concept: when a decision changes, the item is edited,
not appended to.

Each item: what NoteDown does (behavior terms), one line why, and where it
is shown — the mockup page and, if it came from there, the backlog `Nr`.
Items marked **Open** name the question that blocks the decision.

## Vision

**Open** — what NoteDown is for and for whom, and what sets it apart from
existing notes apps.

## Platforms

**Open** — target platforms for the later app (desktop OSes, iOS, Android,
web) and whether all ship at once. The concept covers the three device
tiers in `PROJECT.md` → "Device tiers" in any case.

## Functional areas

No area decided yet. Each new area gets its own `###` section here.
